CPU scaling was not disabled at the OS level during these runs (scaling governor reported ~52%
of max MHz during measurement). All timing data is wall-clock median across iterations as
controlled by Google Benchmark's own time-budget loop (≥1s per benchmark). Relative
comparisons between configs on the same machine are valid; absolute JIT overhead numbers are
indicative only.

## Reproducibility

To reproduce Exp A from scratch:

```bash
UC_BINARY=/path/to/AllBenchmarks
python3 benchmarks/optimize_benchmarks.py "$UC_BINARY" \
    --db benchmarks/benchmarks.duckdb \
    --study-name uc_optim_$(date +%Y%m%d) \
    --n-trials 150 --seed 42 --n-parallel 1 \
    --benchmark-filter 'BM_g:(uc1|uc2|uc7|uc8|uc12|uc14);.*s:MEDIUM;.*t:(jit_overhead|specialized_exec)' \
    --apply-default-filters \
    --output-best benchmarks/results/uc_best_config.json
```

To reproduce Exp E (sensitivity sweep) after Exp A:

```bash
STUDY=sens_uc_$(date +%Y%m%d)
for param_sweep in \
    "fixpoint_max:1,2,3,5,8,15,30" \
    "unroll_max:1,2,4,8,16,32,64,128,256,512" \
    "large_module_max:0,1000,5000,10000,50000,100000" \
    "early_prune:0,1" \
    "o3_final:0,1"; do
  param="${param_sweep%%:*}"; sweep="${param_sweep##*:}"
  python3 benchmarks/sensitivity_analysis.py "$UC_BINARY" \
      --db benchmarks/benchmarks.duckdb \
      --study-name "$STUDY" \
      --optimal-config benchmarks/results/uc_best_config.json \
      --param "$param" --sweep-values "$sweep" \
      --benchmark-filter 'BM_g:(uc1|uc2|uc7|uc8|uc12|uc14);.*s:MEDIUM;.*t:(jit_overhead|specialized_exec|unspecialized)' \
      --reps 1
done
```

Or use the orchestration script: `benchmarks/run_evaluation.sh`.

## Known Caveats

- `CRS_DEFAULT_MAX_FIXPOINT_ITERATIONS=0` combined with `CRS_DEFAULT_O3_FINAL=1` causes
  SIGSEGV (see research.md RQ-10). The search space lower bound is `1`, and the `o3_only`
  ablation config uses `fixpoint_max=1`.
- `CRS_DEFAULT_PIPELINE=1` (function-specialization pipeline) causes core dumps on the full
  UC benchmark filter (see research.md RQ-11). This parameter is excluded from all sweeps.
- CPU frequency scaling was active (~52% of max). JIT overhead timings reflect this;
  speedup ratios are unaffected.
