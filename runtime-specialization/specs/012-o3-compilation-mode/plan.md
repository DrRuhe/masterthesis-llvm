# Implementation Plan: O3 Compilation Mode for Tests and Benchmarks

**Branch**: `012-o3-compilation-mode` | **Date**: 2026-05-16 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `specs/012-o3-compilation-mode/spec.md`

## Summary

All tests and benchmarks must compile and run correctly at `-O3`, enabling fair scientific comparison between JIT-specialised and statically-compiled baselines. The root cause of current -O3 failures is that `IRDumpingPass` is registered at `registerOptimizerLastEPCallback` (after all optimisations), so by the time it runs the IR shapes it relies on for call-site detection have been modified by DAE and other -O3 passes. The fix is to split `IRDumpingPass` into an `IRRewritingPass` (registered at pipeline start, before any optimisation) that handles call-site detection and rewriting, and a slimmed-down `IRDumpingPass` (kept at optimizer-last) that handles blob cloning and serialisation. State is shared via LLVM named metadata. After the split, UC kernel TUs can be compiled at -O3, and smoke tests get paired -O3 RUN lines.

## Implementation Phases

### Phase A: Split IRDumpingPass (prerequisite for everything else)

**A1 — Create `IRRewritingPass`**
- Create `comptime/IRRewritingPass.cpp`
- Move from `IRDumpingPass.cpp`: `SpecLambdaSite`, `SpecFuncPtrSite` structs; all `find*` helpers; `isSpecializeLambda*`/`isSpecOnlyFuncPtr*` predicates; Phase 0, Phase 0b, Phase N, Phase N2 logic
- Add function-name collection (same logic as current Phase FR-010)
- Write function names to `!crs.func_names` named metadata
- Write `!crs.rewriting_done` flag to prevent double-rewriting

**A2 — Update `IRDumpingPass`**
- Remove Phases 0, 0b, N, N2 from `IRDumpingPass.cpp` (moved to rewriting pass)
- Remove function-name collection (now done by rewriting pass)
- Add: read `FuncNames` from `!crs.func_names` named metadata
- Remove `SpecLambdaSites`/`SpecFuncPtrSites`/`LambdaTargets` — no longer needed here
- Keep: DCE roots logic (uses `FuncNames` read from metadata), cloning, vtable BFS, linkage fixup, GlobalDCE, serialisation, constructor emit

**A3 — Update `RuntimeSpecializerPass.h`**
- Add `IRRewritingPass` class declaration (same pattern as `IRDumpingPass`)

**A4 — Update `PassPlugin.cpp`**
- Register `IRRewritingPass` at `registerPipelineStartCallback` (for automatic injection)
- Keep `IRDumpingPass` at `registerOptimizerLastEPCallback`
- Add `IRRewritingPass` to `registerPipelineParsingCallback` (for `-passes=runtime-specialization-IR-rewriting` manual invocation)

**A5 — Update `comptime/CMakeLists.txt`**
- Add `IRRewritingPass.cpp` to the `LLVMRuntimeSpecializationComptimePlugin` source list

**A6 — Verify split correctness**
- Build and run `ninja check-smoke-runtime-specializer` at -O0 (must stay green)
- The WIP test `o3-compilation-basic.cpp` (added in Phase B) is the first -O3 canary

### Phase B: Add -O3 Tests

**B1 — Add WIP canary test**
- `test/WIP/o3-compilation-basic.cpp`: a minimal test that compiles with `-O3 -fpass-plugin=...`, calls `callSpecialized` or `specializeLambda`, and asserts the result is correct
- Run `ninja check-wip-runtime-specializer` to confirm

**B2 — Add -O3 RUN lines to all smoke tests**
- For each file in `test/smoke/` with a `-O0 -fpass-plugin=...` RUN line, add a paired `-O3` line immediately after, using the same FileCheck check-prefix where output is identical
- Tests without a `-fpass-plugin=` flag (`missing-plugin-*`) need no -O3 variant
- For `instruction-count.cpp`: the instruction count output may differ at -O3; add an `-O3`-specific check-prefix `EXE-O3-10` if values differ, or confirm they are the same and share the prefix

**B3 — Verify full -O3 smoke suite**
- Run `ninja check-smoke-runtime-specializer` (both -O0 and -O3 RUN lines pass)

### Phase C: Switch UC Kernel TUs to -O3

**C1 — Update parent `benchmarks/CMakeLists.txt`**
- In the `foreach(UC IN ITEMS UC1 UC2 UC7 UC8 UC12 UC14)` / kernel loop: change `-O0` → `-O3` for `KERN_OBJ` compile commands

**C2 — Update per-UC `CMakeLists.txt` standalone targets**
- Each `benchmarks/use-cases/UC*/CMakeLists.txt` has its own kernel compile command at -O0; update to -O3

**C3 — Verify UC benchmarks build and run**
- Build and execute each UC benchmark binary (or the `AllBenchmarks` target)
- Confirm JIT specialisation still produces correct results (`assertSpecializedIsEquivalent` assertions pass)
